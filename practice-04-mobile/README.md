# SQL-практика: Т-Мобайл

## Схема базы данных

**Т-Мобайл** — мобильный оператор. У абонента есть телефонный номер и тариф с абонентской платой и пакетами минут и гигабайт. Абоненты могут объединяться в семейные группы: у участника указан владелец группы.

Абонентам подключают дополнительные `опции`; одну опцию могут выбрать многие абоненты. У абонента не больше одной `SIM-карты`. Карта может быть запасной — без владельца.

```sql
CREATE TABLE tariffs (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL UNIQUE,
  monthly_fee numeric(10,2) NOT NULL,
  minutes integer NOT NULL,
  gb integer NOT NULL,
  is_archived boolean NOT NULL
);

CREATE TABLE subscribers (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  full_name text NOT NULL,
  phone text NOT NULL UNIQUE,
  tariff_id integer NOT NULL REFERENCES tariffs(id) ON DELETE RESTRICT,
  family_owner_id integer REFERENCES subscribers(id) ON DELETE SET NULL,
  status text NOT NULL DEFAULT 'active'
    CHECK (status IN ('active', 'blocked', 'closed')),
  connected_at date NOT NULL
);

CREATE TABLE options (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL UNIQUE,
  monthly_fee numeric(10,2) NOT NULL CHECK (monthly_fee >= 0)
);

CREATE TABLE subscriber_options (
  subscriber_id integer NOT NULL REFERENCES subscribers(id) ON DELETE CASCADE,
  option_id integer NOT NULL REFERENCES options(id) ON DELETE RESTRICT,
  connected_at date NOT NULL DEFAULT CURRENT_DATE,
  PRIMARY KEY (subscriber_id, option_id)
);

CREATE TABLE sim_cards (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  iccid text NOT NULL UNIQUE,
  subscriber_id integer UNIQUE REFERENCES subscribers(id) ON DELETE RESTRICT,
  is_esim boolean NOT NULL DEFAULT false,
  issued_at date NOT NULL
);
```

## Задания

### [Создать таблицу устройств абонентов](solutions/t01_create_devices.sql)

> **Условие**
>
> Создайте таблицу `devices` для устройств абонентов: у абонента может быть несколько устройств, у устройства — ровно один владелец. Храните владельца, уникальный IMEI, модель, год выпуска от 2007 до 2030 включительно и дату регистрации с текущей датой по умолчанию. Все поля обязательны. При удалении абонента его устройства удаляются.

### [Создать таблицу любимых номеров](solutions/t02_create_favorite_numbers.sql)

> **Условие**
>
> Создайте `favorite_numbers` для связи абонентов с любимыми номерами. Храните пару «кто выбрал — кого выбрали» и дату добавления с текущей датой по умолчанию. Пара служит составным первичным ключом: отдельный `id` не нужен. Нельзя добавить одну пару дважды или выбрать самого себя. При удалении любого из абонентов запись удаляется.

### [Создать таблицу заявок на перенос номера](solutions/t03_create_number_transfers.sql)

> **Условие**
>
> Создайте `number_transfers`: у абонента может быть не больше одной заявки, и каждая заявка относится к одному абоненту. Храните оператора, от которого он переходит, дату заявки и статус `pending`, `done` или `rejected`; статус новой заявки по умолчанию — `pending`. Все поля обязательны. При удалении абонента удаляется и его заявка.

### [Защитить тарифы от ошибок](solutions/t04_tariff_constraints.sql)

> **Условие**
>
> Измените существующую таблицу `tariffs`: добавьте ограничения, запрещающие отрицательные абонентскую плату, минуты и гигабайты (ноль допустим), и установите для `is_archived` значение по умолчанию `false`. Сохраните существующие тарифы.

### [SIM-карта переживает абонента](solutions/t05_sim_cards_set_null.sql)

> **Условие**
>
> Измените внешний ключ `sim_cards.subscriber_id`: при удалении абонента ссылка на него должна становиться пустой (`ON DELETE SET NULL`). Сохраните карты и остальные ограничения таблицы.

### [Удалить закрытые договоры](solutions/t06_close_subscribers.sql)

> **Условие**
>
> Удалите абонентов с закрытым договором. Перед удалением снимите владельцев с их SIM-карт — карты должны остаться запасными. Подключённые опции удалятся каскадно, а участники семейных групп останутся без владельца.

### [Закрыть архивные тарифы](solutions/t07_drop_archived_tariffs.sql)

> **Условие**
>
> Переведите абонентов с архивных тарифов на тариф **«Базовый»**, найдя его по названию, затем удалите архивные тарифы. Сначала обновите абонентов: тариф с подключёнными абонентами удалить нельзя.

### [Удалить старые блокировки](solutions/t08_delete_blocked_without_sim.sql)

> **Условие**
>
> Удалите заблокированных абонентов, подключённых строго раньше 1 января 2025 года, если за ними не закреплена ни одна SIM-карта. Запасные карты без владельца не должны влиять на результат.

### [Добавить нового абонента](solutions/t09_add_subscriber.sql)

> **Условие**
>
> Добавьте абонента **Ирину Соколову** с номером **+7 900 555-12-34**, тарифом **«Базовый»** и датой подключения **1 октября 2026 года**. В семейную группу она не входит. Статус и `id` не указывайте: их задаст база.

### [Самые популярные опции](solutions/t10_top_options.sql)

> **Условие**
>
> Покажите три самые популярные опции: номер опции и число подключивших её абонентов. Сначала самые популярные, при равенстве — опция с меньшим номером.

### [Загруженные тарифы](solutions/t11_busy_tariffs.sql)

> **Условие**
>
> Найдите тарифы, на которых не меньше трёх действующих абонентов. Выведите номер тарифа и число таких абонентов; отсортируйте по числу абонентов по убыванию, затем по номеру тарифа по возрастанию. Заблокированных и закрытых не учитывайте.

### [Размер семейных групп](solutions/t12_family_sizes.sql)

> **Условие**
>
> Для каждого владельца семейной группы покажите его номер и число участников (сам владелец не считается). Абонентов, не входящих в группу, не выводите. Отсортируйте по номеру владельца.

### [Абоненты без SIM-карты](solutions/t13_subscribers_without_sim.sql)

> **Условие**
>
> Найдите абонентов, за которыми не закреплена ни одна SIM-карта. Выведите номер абонента и имя. Учтите, что в таблице карт есть запасные карты с пустым `subscriber_id`.

### [Дорогие и востребованные опции](solutions/t14_expensive_used_options.sql)

> **Условие**
>
> Найдите опции, которые стоят строго дороже средней платы по всем опциям и подключены хотя бы одному абоненту. Выведите номер, название и ежемесячную плату.

### [Доля eSIM](solutions/t15_esim_share.sql)

> **Условие**
>
> По всем SIM-картам, включая запасные, покажите общее число карт, число eSIM и их долю в процентах с точностью до двух знаков после запятой. Результат должен содержать одну строку.

## Запуск и проверка

Нужен Docker с `docker compose`. Запустите практику из этой папки:

```bash
docker compose pull && docker compose up
```

Откройте **http://localhost:8766**: там список заданий, редактор SQL и проверка решений. Если порт занят, задайте другой:

```bash
PORT=9000 docker compose up
```

Решения хранятся в `solutions/`, по одному файлу на задание. Проверить их все разом:

```bash
docker compose run --rm runner runner ci --pack /pack.enc --solutions /solutions
```
