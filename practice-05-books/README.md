# SQL-практика: библиотека

Тема: **Нормализация баз данных: 1NF, 2NF, 3NF и BCNF**.

## Схема базы данных

Городская библиотека ведёт учёт книг, читателей и выдач. Каталог хранит шифр и название темы в каждой записи книги, а также до трёх авторов в отдельных полях. Справочник тем существует отдельно: каталог с ним не связан, поэтому названия могут расходиться, а некоторые шифры — отсутствовать в справочнике.

```sql
CREATE TABLE topics (
  code text PRIMARY KEY,
  title text NOT NULL
);

CREATE TABLE book_catalog (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  topic_code text NOT NULL,
  topic_title text NOT NULL,
  title text NOT NULL,
  book_type text NOT NULL,
  pages integer NOT NULL,
  published_year integer NOT NULL,
  author1 text NOT NULL,
  author2 text,
  author3 text
);

CREATE TABLE readers (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  full_name text NOT NULL,
  card_no text NOT NULL UNIQUE,
  registered_at date NOT NULL,
  is_active boolean NOT NULL
);

CREATE TABLE loans (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  book_id integer NOT NULL REFERENCES book_catalog(id),
  reader_id integer NOT NULL REFERENCES readers(id),
  issued_at date NOT NULL,
  returned_at date,
  fine numeric(10,2) NOT NULL
);
```

## Задания

### [Книги с несколькими авторами](solutions/t01_books_with_second_author.sql)

> **Условие**
>
> Выведите номер, название и второго автора книг, у которых второй автор указан. Отсортируйте по номеру книги. Повторы не убирайте; соединения не используйте.

### [Разные названия одной темы](solutions/t02_topic_title_conflicts.sql)

> **Условие**
>
> Найдите шифры тем, которым в каталоге соответствует больше одного названия. Выведите `topic_code` и число разных названий `title_variants`, отсортируйте по шифру. Используйте группировку и `HAVING`, без соединений.

### [Темы на одной книге](solutions/t03_single_book_topics.sql)

> **Условие**
>
> Выведите шифры тем, у которых в каталоге ровно одна книга, по возрастанию шифра. Используйте группировку и `HAVING`, без соединений.

### [Шифры тем вне справочника](solutions/t04_unknown_topic_codes.sql)

> **Условие**
>
> Выведите без повторов шифры тем, которые есть в каталоге, но отсутствуют в справочнике. Отсортируйте по шифру. Используйте подзапрос, без соединений.

### [Добить справочник тем](solutions/t05_fill_missing_topics.sql)

> **Условие**
>
> Добавьте в `topics` каждый отсутствующий шифр из каталога один раз. Название возьмите из книг: минимальное по алфавиту для этого шифра. Существующие темы и каталог не изменяйте. Используйте подзапрос, без соединений.

### [Выровнять названия тем по справочнику](solutions/t06_sync_topic_titles.sql)

> **Условие**
>
> Обновите названия тем в каталоге по справочнику для книг, чьи шифры есть в `topics`. Остальные книги и справочник не изменяйте. Используйте подзапрос, без соединений.

### [Таблица авторов книги](solutions/t07_create_book_authors.sql)

> **Условие**
>
> Создайте `book_authors` с обязательными `book_id` и `author_name` и составным первичным ключом из этих полей. `book_id` ссылается на `book_catalog(id)` с каскадным удалением. Отдельный `id` и данные не добавляйте; другие таблицы не меняйте.

### [Связать каталог со справочником](solutions/t08_link_catalog_to_topics.sql)

> **Условие**
>
> Измените `book_catalog`: добавьте внешний ключ `topic_code` на `topics(code)` с `ON DELETE RESTRICT` и удалите колонку `topic_title`. Сохраните строки каталога и не изменяйте справочник.

## Запуск и проверка

Нужен Docker с `docker compose`. Запустите практику из этой папки:

```bash
docker compose pull && docker compose up
```

Откройте **http://localhost:8766**: там список заданий, редактор SQL и проверка решений. Если порт занят, задайте другой:

```bash
PORT=9000 docker compose up
```

Решения хранятся в `solutions/`, по одному файлу на задание. Проверить их все разом:

```bash
docker compose run --rm runner runner ci --pack /pack.enc --solutions /solutions
```
