# SQL-практика: городская афиша

## Схема базы данных

Городская **афиша** продаёт билеты на мероприятия.

Каждое `мероприятие` относится к одной `категории` — концерт, стендап, театр, спорт — и чаще всего проходит в каком-то `зале`. Если зал не указан, мероприятие идёт онлайн-трансляцией: смотреть можно откуда угодно, адреса у него нет.

`Билет` всегда куплен на конкретное мероприятие конкретным `покупателем` и хранит свою цену — она может отличаться от базовой цены мероприятия. Залы в афише бывают и без мероприятий, а мероприятия — без единого проданного билета.

```sql
CREATE TABLE categories (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL,
  is_active boolean NOT NULL
);

CREATE TABLE venues (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL,
  address text NOT NULL,
  capacity integer NOT NULL
);

CREATE TABLE events (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL,
  category_id integer NOT NULL REFERENCES categories(id),
  venue_id integer REFERENCES venues(id),
  starts_on date NOT NULL,
  base_price numeric(10,2) NOT NULL
);

CREATE TABLE buyers (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  full_name text NOT NULL,
  phone text NOT NULL UNIQUE,
  registered_at date NOT NULL,
  is_subscriber boolean NOT NULL
);

CREATE TABLE tickets (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  event_id integer NOT NULL REFERENCES events(id),
  buyer_id integer NOT NULL REFERENCES buyers(id),
  price numeric(10,2) NOT NULL,
  seat_no integer,
  bought_on date NOT NULL
);
```

## Задания

### [Мероприятия в залах](solutions/t01_events_in_venues.sql)

> **Условие**
>
> Соедините `events` с `venues` по `events.venue_id = venues.id` и выведите три колонки: `event_title` — `events.title`, `venue_title` — `venues.title`, `address` — `venues.address`.
>
> - мероприятия с пустым `events.venue_id` в результат не попадают;
> - порядок строк не проверяется.

### [Афиша с категорией и залом](solutions/t02_events_with_category_and_venue.sql)

> **Условие**
>
> Выведите по строке на каждое мероприятие из `events`, включая мероприятия с пустым `venue_id`. Колонки: `event_title` — `events.title`, `category_title` — `categories.title`, `venue_title` — `venues.title` (`NULL`, если зал не указан).
>
> - категорию берите по `events.category_id = categories.id`;
> - зал — по `events.venue_id = venues.id`, и ни одно мероприятие при этом теряться не должно;
> - порядок строк не проверяется.

### [Сколько мероприятий в каждом зале](solutions/t03_events_per_venue.sql)

> **Условие**
>
> Для каждой строки `venues` выведите `venue_title` — `venues.title` и `events_count` — число мероприятий `events` с этим `venue_id`.
>
> - залы без мероприятий остаются в результате со значением `0`;
> - считайте именно мероприятия (`COUNT` по колонке `events`, не `COUNT(*)`), иначе у пустого зала получится `1`;
> - порядок строк не проверяется.

### [Билеты подписчиков](solutions/t04_subscriber_tickets.sql)

> **Условие**
>
> Соедините `tickets` с `buyers` по `buyer_id` и с `events` по `event_id`. Оставьте строки, где `buyers.is_subscriber = true`. Колонки: `buyer_name` — `buyers.full_name`, `event_title` — `events.title`, `price` — `tickets.price`.
>
> - порядок строк не проверяется.

### [Выручка по категориям](solutions/t05_revenue_per_category.sql)

> **Условие**
>
> Соедините `tickets` с `events` по `event_id` и с `categories` по `category_id`, сгруппируйте по категории и выведите `category_title` — `categories.title` и `revenue` — `SUM(tickets.price)`.
>
> - категории без проданных билетов в результат не попадают;
> - порядок строк не проверяется.

### [Покупатели с тремя билетами и больше](solutions/t06_busy_buyers.sql)

> **Условие**
>
> Соедините `buyers` с `tickets` по `buyer_id`, сгруппируйте по покупателю и оставьте группы, где билетов **не меньше 3**. Колонки: `buyer_name` — `buyers.full_name`, `tickets_count` — число билетов покупателя.
>
> - отбор по числу билетов делайте фильтром групп, а не `WHERE`;
> - порядок строк не проверяется.

### [Онлайн-трансляции](solutions/t07_online_events.sql)

> **Условие**
>
> Выведите мероприятия `events`, у которых `venue_id` пустой (`IS NULL`), с категорией по `events.category_id = categories.id`. Колонки: `event_title` — `events.title`, `category_title` — `categories.title`, `starts_on` — `events.starts_on`.
>
> - порядок строк не проверяется.

### [Мероприятия без проданных билетов](solutions/t08_events_without_tickets.sql)

> **Условие**
>
> Выведите `event_id` — `events.id` и `event_title` — `events.title` для мероприятий, на которые нет ни одной строки в `tickets`.
>
> - решайте **подзапросом** (`NOT EXISTS` или `NOT IN`), соединение таблиц в этом задании запрещено;
> - порядок строк не проверяется.

### [Билеты дороже средних по мероприятию](solutions/t09_tickets_above_event_avg.sql)

> **Условие**
>
> Из `tickets` выведите `ticket_id` — `tickets.id`, `event_id` — `tickets.event_id`, `price` — `tickets.price` для строк, где `price` **строго больше** средней `price` по всем билетам того же `event_id`.
>
> - решайте коррелированным подзапросом, соединение таблиц в этом задании запрещено;
> - порядок строк не проверяется.

### [Залы с выручкой выше средней](solutions/t10_venues_above_avg_revenue.sql)

> **Условие**
>
> Промежуточную выручку залов посчитайте в `WITH`: соедините `venues`, `events` (по `venue_id`) и `tickets` (по `event_id`), сгруппируйте по залу, выручка — `SUM(tickets.price)`. Затем выведите `venue_title` — `venues.title` и `revenue` — выручку зала для залов, чья выручка **строго больше** среднего значения выручки по этой же промежуточной выборке.
>
> - залы, у которых нет ни одного проданного билета, в промежуточную выборку не попадают, а значит не влияют на среднее;
> - решение обязано использовать `WITH`;
> - порядок строк не проверяется.

### [Номер покупки внутри покупателя](solutions/t11_ticket_number_per_buyer.sql)

> **Условие**
>
> Из `tickets` выведите `ticket_id` — `tickets.id`, `buyer_id`, `bought_on` и `ticket_no` — номер строки внутри покупателя.
>
> - `ticket_no` считайте **оконной функцией** `ROW_NUMBER()` с разбиением по `buyer_id` и упорядочиванием по `bought_on`, затем по `id` (возрастание в обоих случаях);
> - `GROUP BY` здесь не подходит: нужны все строки `tickets`;
> - порядок строк не проверяется.

### [Топ-3 мероприятия в каждой категории](solutions/t12_top_events_in_category.sql)

> **Условие**
>
> Выручку мероприятия считайте как `SUM(tickets.price)` по его билетам, соединяя `tickets`, `events` и `categories`. Внутри каждой категории проставьте место по убыванию выручки оконной функцией `DENSE_RANK()` с разбиением по категории, затем оставьте строки с местом **не больше 3**.
>
> - колонки: `category_title` — `categories.title`, `event_title` — `events.title`, `revenue` — выручка мероприятия, `revenue_rank` — место внутри категории;
> - алиас оконной функции нельзя использовать в `WHERE` того же `SELECT` — заверните выборку в подзапрос или `WITH` и фильтруйте снаружи;
> - мероприятия без билетов в расчёт не входят;
> - порядок строк не проверяется.
