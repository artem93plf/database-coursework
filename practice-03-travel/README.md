# SQL-практика: Т-Путешествия

## Схема базы данных

**Т-Путешествия** — сервис, где клиенты бронируют отели и покупают авиа- и ж/д-билеты.

Места собраны в справочник `places` деревом: страна → регион → город. `Отели` стоят в городах. `Клиент` живёт в каком-то городе и имеет уровень программы лояльности.

У клиента бывают два вида покупок: `брони отелей` (заезд, число ночей, питание, цена, статус и оценка) и `билеты` (самолёт или поезд в город назначения, цена и статус).

```sql
CREATE TABLE places (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  kind text NOT NULL CHECK (kind IN ('country', 'region', 'city')),
  parent_id integer REFERENCES places(id)
);

CREATE TABLE hotels (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  city_id integer NOT NULL REFERENCES places(id) DEFERRABLE INITIALLY DEFERRED,
  stars integer NOT NULL CHECK (stars BETWEEN 1 AND 5)
);

CREATE TABLE clients (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  full_name text NOT NULL,
  home_city_id integer NOT NULL REFERENCES places(id) DEFERRABLE INITIALLY DEFERRED,
  level text NOT NULL CHECK (level IN ('base', 'pro', 'premium')),
  registered_at date NOT NULL
);

CREATE TABLE hotel_bookings (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  client_id integer NOT NULL REFERENCES clients(id),
  hotel_id integer NOT NULL REFERENCES hotels(id),
  booked_at date NOT NULL,
  check_in date NOT NULL,
  nights integer NOT NULL CHECK (nights > 0),
  guests integer NOT NULL CHECK (guests > 0),
  board text CHECK (board IN ('BB', 'HB', 'AI')),
  price numeric(10,2) NOT NULL,
  status text NOT NULL CHECK (status IN ('confirmed', 'completed', 'cancelled')),
  rating integer CHECK (rating BETWEEN 1 AND 5)
);

CREATE TABLE tickets (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  client_id integer NOT NULL REFERENCES clients(id),
  kind text NOT NULL CHECK (kind IN ('avia', 'train')),
  to_city_id integer NOT NULL REFERENCES places(id) DEFERRABLE INITIALLY DEFERRED,
  bought_at date NOT NULL,
  depart_date date NOT NULL,
  price numeric(10,2) NOT NULL,
  status text NOT NULL CHECK (status IN ('paid', 'used', 'refunded'))
);
```

## Задания

### [Пять самых дорогих броней](solutions/t01_top_expensive_bookings.sql)

> **Условие**
>
> Покажите **пять самых дорогих броней отелей** за всё время, независимо от статуса. Для каждой выведите номер брони, номер отеля, дату заезда и стоимость.
>
> Самая дорогая — первой. Если стоимость совпадает, выше идёт бронь с меньшим номером.
>

### [Вторая страница билетов](solutions/t02_tickets_second_page.sql)

> **Условие**
>
> В приложении билеты показываются списком **по 10 штук на страницу**: сначала с самой ранней датой отправления, при одинаковой дате — с меньшим номером билета.
>
> Выведите, что окажется на **второй странице**: номер билета, тип транспорта, город назначения, дату отправления и стоимость. Если билетов не больше десяти, вторая страница пуста.
>

### [Сводка по броням](solutions/t03_bookings_summary.sql)

> **Условие**
>
> Подготовьте **одну строку сводки** по всем броням отелей (любого статуса):
>
> - сколько всего броней;
> - у скольких из них клиент **поставил оценку**;
> - сколько **разных клиентов** хоть раз бронировали отель;
> - **средняя оценка** — только по броням, где она есть, с округлением до двух знаков после запятой.
>

### [Билеты по типу и статусу](solutions/t04_tickets_by_kind_status.sql)

> **Условие**
>
> Для каждого сочетания **типа транспорта** (самолёт или поезд) и **статуса билета** покажите: тип, статус, сколько таких билетов, самую низкую и самую высокую цену.
>
> Выводите только сочетания, которые реально встречаются. Отсортируйте по типу транспорта, затем по статусу — оба по алфавиту.
>

### [Брони по типу питания](solutions/t05_board_stats.sql)

> **Условие**
>
> Отдел продаж хочет понять, какое питание выбирают чаще. По броням, которые **не отменены**, для каждого варианта питания покажите: вариант питания, число броней и среднюю стоимость брони с округлением до двух знаков.
>
> Брони **без питания** — тоже отдельная строка с пустым вариантом питания: её нельзя терять. Порядок строк не важен.
>

### [Короткие и длинные поездки](solutions/t06_stay_length_groups.sql)

> **Условие**
>
> Разделите **неотменённые** брони по длительности проживания на три группы: **«1-3»** — от одной до трёх ночей, **«4-7»** — от четырёх до семи, **«8+»** — восемь ночей и больше.
>
> Для каждой группы покажите название группы, число броней и их общую стоимость. Группы без броней не выводите. Порядок строк не важен.
>

### [Доля отмен по отелям](solutions/t07_hotel_cancel_share.sql)

> **Условие**
>
> Для каждого отеля, где была хотя бы одна бронь, покажите: номер отеля, сколько всего броней, сколько из них **отменено** и **процент отмен** от всех броней отеля с точностью до двух знаков после запятой (например, 1 отмена из 3 броней — это 33.33).
>
> Отсортируйте по номеру отеля по возрастанию.
>

### [Выручка за март](solutions/t08_march_revenue.sql)

> **Условие**
>
> Посчитайте по **завершённым** проживаниям с заездом **в марте 2026 года** (с 1 по 31 марта включительно): общую выручку и средний чек брони с округлением до двух знаков.
>
> Отчёт всегда должен состоять из одной строки: если таких броней не было, и выручка, и средний чек равны **0**, а не пустому значению.
>

### [Популярные отели](solutions/t09_busy_hotels.sql)

> **Условие**
>
> Найдите отели, где **завершилось не меньше трёх проживаний**. Для каждого выведите номер отеля, число завершённых проживаний и выручку по ним.
>
> Отменённые и ещё не начавшиеся брони не учитываются ни в счёте, ни в выручке. Сначала отели с наибольшим числом проживаний, при равенстве — с меньшим номером.
>

### [Клиенты с крупными тратами на билеты](solutions/t10_big_ticket_spenders.sql)

> **Условие**
>
> Найдите клиентов, которые потратили на билеты **больше 50 000 рублей**. Возвращённые билеты не считаются: ни в число билетов, ни в сумму.
>
> Для каждого клиента выведите номер клиента, число его билетов и потраченную сумму. Сначала те, кто потратил больше; при равной сумме — клиент с меньшим номером.
>

### [Брони дороже средней](solutions/t11_above_average_bookings.sql)

> **Условие**
>
> Найдите брони отелей, стоимость которых **строго выше средней стоимости всех броней** (среднее считается по всем броням любого статуса).
>
> Выведите номер брони, номер клиента и стоимость. Порядок строк не важен.
>

### [Premium-клиенты в пятизвёздочных отелях](solutions/t12_premium_luxury_bookings.sql)

> **Условие**
>
> Найдите **неотменённые** брони, которые клиенты уровня **premium** сделали в **пятизвёздочных** отелях.
>
> Выведите номер брони, номер клиента, номер отеля и стоимость. Порядок строк не важен; если таких броней нет — пустой результат.
>

### [Билеты дороже обычного для клиента](solutions/t13_tickets_above_client_avg.sql)

> **Условие**
>
> Найдите билеты, которые стоят **строго дороже, чем в среднем стоят билеты этого же клиента** (среднее по всем его билетам любого статуса).
>
> Выведите номер билета, номер клиента и стоимость. Порядок строк не важен.
>

### [Отели с выручкой выше средней](solutions/t14_top_hotels_cte.sql)

> **Условие**
>
> Посчитайте для каждого отеля выручку по **завершённым** проживаниям. Затем найдите **среднюю выручку** среди отелей, у которых были завершённые проживания, и выведите отели, чья выручка **строго выше** этой средней.
>
> Для каждого — номер отеля и выручка. Сначала самые доходные, при равной выручке — отель с меньшим номером.
>

### [Билеты по России](solutions/t15_russia_tickets_recursive.sql)

> **Условие**
>
> Посчитайте билеты **в города России** — в любом её регионе. Возвращённые билеты не учитываются.
>
> Для каждого типа транспорта выведите тип, число билетов и их общую стоимость. Отсортируйте по типу транспорта по алфавиту. Тип, по которому таких билетов нет, не выводите.
>
> Список городов не перечисляйте вручную: найдите все места внутри России, спускаясь по справочнику мест от страны к регионам и городам.
